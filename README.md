# qqmusic

QQ 音乐评论抓取 / 检索 / AI 情感分析服务。

从 `netease163` 项目独立出来的姊妹项目：同样的分层结构、同样的 AI 情感标签体系，
但数据模型按 QQ 音乐的实际字段重新设计（两边不可混用，原因见下）。

## 为什么独立而不是并入 netease163

不是偷懒，是实测下来**数据模型有四项硬不兼容**：

| 维度 | 网易 | QQ 音乐 |
|---|---|---|
| 评论 ID | 整数 | **66~110 字符字符串** (`1!CRHVjInz...`) |
| 时间单位 | 毫秒 | **秒** |
| 歌曲 ID | 纯数字 | 纯数字，**区间与网易重叠**，两库合并必然撞车 |
| 正文 | 纯文本 | 含 `[em]e400867[/em]` 表情占位码，需清洗 |

合并意味着把 `Song.id` 改成复合主键、改全部路由、迁移存量数据。
而 QQ 侧的价值还没验证，不值得为不确定性买单。

## 接口实测结论（2026-09）

这些是踩过坑才知道的，改代码前先看：

1. **不需要登录**。真 Cookie / 假 Cookie / 无 Cookie 三组对照，返回结果完全一致。
   所以本项目没有登录模块 —— 不用维护 Cookie、不用处理验证码。
2. **`pagesize` 硬上限 25**。传 50/100/200 不会报错，而是**静默退化成只返回 10 条**，
   比 25 还少。代码里已强制 clamp。
3. **单歌可翻深度约 2 万条**。超过后返回空列表且 `code=0`，不是报错也不是风控
   （休息 + 慢速重试仍为空，同期小歌翻页正常）。
   入库时会记 `completed` 标志区分「抓全了」和「被截断」。
4. **热评固定 15 条**，跟网易一样，登录也不解决。
5. 搜索只能用 `search_for_qq_cp`；`client_search_cp` 和 `musicu.fcg` 已失效。

### 可抓取量参考

| 歌曲 | 标称评论数 | 实际可抓 |
|---|---|---|
| 张三的歌 | 1,222 | 全部 |
| 说好不哭 | 19,887 | 全部 |
| 孤勇者 | 153,698 | 约 21,929（14%） |
| 稻香 | 73,379 | 约 25,750（35%） |

**选歌建议**：优先挑评论数 2 万以内的歌，能 100% 抓全。

### 内容质量提示

抽样显示 QQ 音乐评论**中位数仅 10 字，33% 短于 6 字，74% 零赞**，
深翻页的水评比例更高。所以「能抓 2 万条」的优势要打折 ——
真正有价值的集中在前几百条 + 热评。抓取时默认开启水评过滤。

## 安装

```bash
pip install -r requirements.txt
```

## 用法

```bash
# 搜歌, 拿 songid
python -m qqmusic.cli search 孤勇者

# 抓评论 (预览)
python -m qqmusic.cli comments 331839675 --pages 5

# 抓评论并入库
python -m qqmusic.cli comments 331839675 --save

# 看统计
python -m qqmusic.cli stats

# 起 API 服务 (默认端口 8020, 避免与其它本地服务冲突)
python -m qqmusic.cli serve
```

## 环境变量

| 变量 | 说明 |
|---|---|
| `DATABASE_URL` | 数据库连接，默认项目内 SQLite |
| `QQMUSIC_API_KEY` | 设置后 API 需带 `X-API-Key` 请求头；不设则不鉴权 |
| `LOG_LEVEL` | 日志级别，默认 INFO |
| `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` | AI 情感分析用 |

## 目录结构

```
qqmusic/
├── utils/      常量 / 日志 / 时间 / 正文清洗
├── storage/    SQLAlchemy 模型与连接
├── spiders/    base / comment / search
├── api/        FastAPI 服务
├── ai/         LLM 情感分析 (26 标签体系, 与网易项目一致)
└── cli.py      命令行入口
```

## 已知限制

- 只做评论抓取，不做歌词 / 歌单 / 榜单
- 无定时调度（网易项目那套 APScheduler 暂未移植）
- 评论去重靠 `(song_id, comment_id)` 唯一约束
